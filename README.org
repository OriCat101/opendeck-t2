#+title: opendeck-touchbar

An [[https://github.com/nekename/OpenDeck][OpenDeck]] device plugin that turns the MacBook Touch Bar into a deck on Asahi Linux. OpenDeck key images are drawn on the bar and touches become key presses.

The plugin owns the Touch Bar directly and *replaces tiny-dfr*: there is no function row, and the bar is blank while OpenDeck is not running.

* Status

Early. Developed and tested on a MacBookPro17,1 (M1 13") running NixOS.

- Works: drawing, touch input, running without root, connecting to OpenDeck as a 1x16 key device, loading through nix-opendeck's home-manager module, device access through the udev rules package.
- Keys are drawn like tiny-dfr's: rounded grey buttons with the icon blended in, lighter while touched.
- Untested: other Touch Bar models (M2 13", Intel T2 Macs).

* How it works

- Display: the =adp= DRM card (60x2008, portrait) is driven with a dumb buffer; drawing is rotated to a 2008x60 landscape bar.
- Touch: the =apple_z2= multitouch device is read through evdev and mapped to 16 equal key cells; each cell shows one rounded button.
- Backlight: set from OpenDeck's brightness; the bar dims after 30 s without touch and turns off after 60 s (the panel is OLED). The first touch on a dark bar only wakes it. Typing or using the trackpad (or any other keyboard or mouse) also wakes the bar and keeps it on; the settings button next to the plugin in OpenDeck's plugin list switches that off and on again (there is no settings window, the button is the switch, and the bar lights up to confirm).

* Requirements

- An Apple Silicon MacBook Pro with a Touch Bar, running Asahi Linux.
- Nix with flakes.
- tiny-dfr stopped or disabled: only one program can own the Touch Bar display.

* Try it without installing

This lasts until the next reboot. Device numbers may differ on your machine; check =/sys/class/drm= and =/proc/bus/input/devices=.

#+begin_src sh
sudo systemctl stop tiny-dfr
sudo chown $USER /dev/dri/card2 /dev/input/event3 /sys/class/backlight/228600000.dsi.0/brightness

nix run .#opendeck-touchbar -- --demo
#+end_src

The demo draws 16 numbered keys (0 in green at the left end, 15 in red at the right) and prints =down N= / =up N= for touches. If the bar is upside down, set =OPENDECK_TOUCHBAR_FLIP=1=.

Then, with OpenDeck:

#+begin_src sh
nix run .#install    # copies the plugin to ~/.config/opendeck/plugins
nix run .#opendeck
#+end_src

A "Touch Bar" device with 1x16 keys should appear. =sudo systemctl start tiny-dfr= brings the function row back.

* NixOS

This repo ships no module of its own. OpenDeck, its home-manager module and store-based plugin loading come from [[https://github.com/missmoode/nix-opendeck][missmoode/nix-opendeck]]; this flake provides the plugin package in the layout that module expects, plus the udev rules as its =udev= output.

Flake inputs:

#+begin_src nix
{
  opendeck = {
    url = "github:missmoode/nix-opendeck";
    inputs.nixpkgs.follows = "nixpkgs";
  };
  opendeck-touchbar = {
    url = "github:OriCat101/opendeck-t2";
    inputs.nixpkgs.follows = "nixpkgs";
    inputs.opendeck.follows = "opendeck";
  };
}
#+end_src

Let =nixpkgs= follow yours. OpenDeck's webview has to be built against the same glibc as your system's Mesa, otherwise it aborts with =Could not create default EGL display=. Do not make nix-opendeck's =deno-nixpkgs= input follow anything.

System configuration (device access, and tiny-dfr off):

#+begin_src nix
{ inputs, pkgs, ... }:
let
  touchbar = inputs.opendeck-touchbar.packages.${pkgs.stdenv.hostPlatform.system}.default;
in
{
  services.udev.packages = [ touchbar.udev ];
  users.groups.touchbar.members = [ "alice" ];

  hardware.apple.touchBar.enable = false; # tiny-dfr
}
#+end_src

The rules give the =touchbar= group access to the display, the touch device and the backlight, and keep the compositor away from the Touch Bar (the seat rules tiny-dfr normally ships). Log out and back in after rebuilding so the group applies.

Waking the bar from the keyboard and trackpad needs no device access: the plugin asks the Wayland compositor (=ext-idle-notify-v1=) whether the user is active. On compositors without that protocol, or outside Wayland, only touch wakes the bar. The setting is stored by OpenDeck as ={"wake_on_input": true}= in =~/.config/opendeck/settings/opendeck-touchbar.sdPlugin.json=.

Home-manager (OpenDeck itself and the plugin):

#+begin_src nix
{ inputs, pkgs, ... }:
{
  imports = [ inputs.opendeck.homeManagerModules.default ];

  programs.opendeck = {
    enable = true;
    plugins = [
      inputs.opendeck-touchbar.packages.${pkgs.stdenv.hostPlatform.system}.default
    ];
    settings.updatecheck = false;
  };
}
#+end_src

See the nix-opendeck README for the module's other options (settings, reload and restart behaviour, more plugins).

** Full-width keys

OpenDeck renders every key as a 144x144 square, so on the wide Touch Bar buttons a background colour only covers a square in the middle. This flake's =opendeck= package is nix-opendeck's OpenDeck with a small frontend patch that renders Touch Bar keys at the buttons' proportions (327x144), so backgrounds fill the whole button and titles get more room:

#+begin_src nix
programs.opendeck.package = inputs.opendeck-touchbar.packages.${pkgs.stdenv.hostPlatform.system}.opendeck;
#+end_src

This builds OpenDeck locally. In the OpenDeck window the Touch Bar's keys are then shown wide as well. Without the patch everything still works, with square images.

Pictures you pick for a key keep their proportions and are shown whole, so a picture spans the full key only if it is about as wide as the key (2.27:1). Pictures picked before switching to the patched OpenDeck were stored as squares with bars; pick them again. Images drawn by other plugins stay square.

The patch (=nix/patches/opendeck-wide-keys.patch=) is a stopgap: it hardcodes the Touch Bar's device namespace and key size in OpenDeck's frontend. It should probably be upstreamed at some point, as a way for device plugins to tell OpenDeck their key size when registering a device.

** With an unpatched OpenDeck

A stock OpenDeck changes the plugin binary's permissions on start, so a link into the Nix store does not work there. =nix run .#install= copies the plugin into =~/.config/opendeck/plugins= instead.
